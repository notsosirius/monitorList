新增/变更需求
需求1：新建记录时报关单号重复——先提示再录入（不做唯一约束）
目标：避免误操作造成重复录入，但业务上允许同一报关单号存在多条记录。
1.1 原则
•	数据库不加唯一约束/唯一索引（报关单号允许重复）。
•	重复校验为业务校验，且必须“先提示、用户确认后才插入”。
1.2 两阶段交互流程
阶段A：预检（不落库）
•	用户点击“保存新建”（录入台账：1/2/3 来自插件 + 输入 4/5/6）。
•	后端根据 报关单号 查询是否已存在记录：
o	不重复：直接插入并返回成功；
o	重复：不插入，返回“重复提示”，前端弹窗提示“报关单号已存在（X 条），是否仍要新增？”并提供【仍要新增】【取消】。
阶段B：确认创建（落库）
•	用户点【仍要新增】后，前端再次发起创建请求，并携带确认参数（如 confirmDuplicate=true），后端才执行插入。
1.3 接口约定（建议）
•	POST /ledger（创建记录：字段 1/2/3/4/5/6）
o	不重复：201 Created + 新记录
o	重复且未确认：409 Conflict + 响应体包含
	code: "DUPLICATE_DECL_NO"
	message: "报关单号已存在，是否仍要新增？"
	existingCount: number
	可选：existingIds: number[] 或“最近一条记录摘要”
o	重复且确认：201 Created + 新记录
1.4 验收
•	同报关单号第一次新增：直接成功。
•	第二次新增：先 409 提示且数据库未插入；点击确认后才插入成功。
•	数据库无唯一约束但流程可控。
